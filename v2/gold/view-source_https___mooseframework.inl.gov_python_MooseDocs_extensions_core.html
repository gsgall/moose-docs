class="row"><div class="moose-content col s12 m12 l10"><section id="396fc32e-df3c-40bf-ad9f-5b03c25ccc85" data-section-level="1" data-section-text="Core Extension"><h1 id="core-extension">Core Extension</h1><p>The core extension is the portion of the MooseDocs language that is designed to mimic <a href="https://en.wikipedia.org/wiki/Markdown">markdown</a> syntax. MooseDown is far more strict than traditional <a href="https://en.wikipedia.org/wiki/Markdown">markdown</a> implementations. Therefore, the following sections should be read in detail to understand the supported syntax, especially if you are familiar with more general markdown formats.</p><p>Syntax is separated into two groups: <a href="core.html#core-block">block</a> and <a href="core.html#core-inline">inline</a>. Block content is made of items that make, as the name suggests, blocks of text. Blocks of text include items such as code snippets, quotations, and paragraphs themselves. On the other hand, inline items are those that are applicable to small portions of text (e.g., words). Bold and italics are two examples of inline items.</p><div class="card moose-alert moose-alert-note"><div class="card-title moose-alert-title"><i class="material-icons moose-inline-icon">comment</i><span class="moose-alert-title-brand">note:</span>MooseDown is a restricted version of <a href="https://en.wikipedia.org/wiki/Markdown">markdown</a>.</div><div class="card-content"><div class="moose-alert-content"><p>To unify content and to create a fast parser a strict, limited set of markdown is being used to define the MooseDocs syntax. The following sections detail the syntax.</p></div></div></div><section class="scrollspy" id="407cffc8-0d38-49ee-8eb9-a14988982551" data-section-level="2" data-section-text="Settings"><h2 id="settings">Settings</h2><p>In general, most block level syntax and some inline syntax accepts key-value pair settings. Where the settings appear within the syntax varies and is detailed in the following sections. <a href="#settings-example">Example 1</a> show how the settings are specified in <a href="core.html#links">Links</a>. However, the settings are applied in a uniform manner. Foremost, the key and value are separated by an equal (<code>=</code>) sign <strong>without spaces</strong> surrounding. The value may contain spaces, with the space after the equal sign being the exception.</p><p>If syntax has settings then the key-value pairs, the default value (if any), and a short description will be provided in a table. For example, <a href="#code-settings">Table 1</a> lists the available settings for the fenced code blocks discussed in the <a href="core.html#fenced-code">Code</a> section.</p><div class="card moose-float"><div class="card-content"><p class="moose-caption"><span class="moose-caption-heading">Example 1: </span><span class="moose-caption-text" id="settings-example">Example use of settings within <a href="core.html#links">Links</a>. Settings are key-value pairs that are specified with a separating equal sign (no spaces exist on either side).</span></p><div class="moose-devel-example"><ul class="tabs"><li class="tab"><a href="#d6d3d5df-5695-4c09-b60b-8d9ecf9e7090">Markdown</a></li><li class="tab"><a href="#73285f3e-6f91-484f-ab6b-5c02c22f0c23">HTML</a></li></ul><div class="moose-devel-example-code" id="d6d3d5df-5695-4c09-b60b-8d9ecf9e7090"><pre>[google](https://www.google.com style=color:teal;)</pre></div><div class="moose-devel-example-html" id="73285f3e-6f91-484f-ab6b-5c02c22f0c23"><p><a href="https://www.google.com" style="color:teal;">google</a></p></div></div></div></div></section><section class="scrollspy" id="a9da9ed4-edec-4b4a-93ed-b8e426aa3af8" data-section-level="2" data-section-text="Block Syntax"><h2 id="core-block">Block Syntax</h2><p>Block level content, as the name suggests, are blocks of text. In all cases, blocks must begin and end with empty lines (with the exception of the start and end of the file). This restriction allows for special characters such as the hash (<code>#</code>) to be used at the start of a line without conflicting with heading creation (see <a href="core.html#headings">Headings</a>). Additionally, this allows content and settings to span multiple lines.</p><section id="f2b7cf90-6f00-4402-a14f-4f6d1059792f" data-section-level="3" data-section-text="Code"><h3 id="fenced-code">Code</h3><p>Code blocks or snippets&mdash;as shown in <a href="#fenced-code-example">Example 2</a>&mdash;are created by enclosing the code for display in triple back-ticks (<code></code>`), this is commonly referred to as fenced code blocks. Two requirements exist for creating the code blocks:</p><ol class="browser-default" start="1"><li><p>the back-ticks must be preceded by an empty line and </p></li><li><p>the back-ticks must start at the beginning of a line.</p></li></ol><p>Settings for code blocks are defined by key-value pairings that follow the back-ticks; <a href="#code-settings">Table 1</a> lists the available settings for code blocks.</p><div class="card moose-float"><div class="card-content"><p class="moose-caption"><span class="moose-caption-heading">Example 2: </span><span class="moose-caption-text" id="fenced-code-example">Basic fenced code block.</span></p><div class="moose-devel-example"><ul class="tabs"><li class="tab"><a href="#bff6ac59-db4e-48ec-bbdf-92ade12c40c4">Markdown</a></li><li class="tab"><a href="#530174cf-1aab-42a2-a393-951d0baf912d">HTML</a></li></ul><div class="moose-devel-example-code" id="bff6ac59-db4e-48ec-bbdf-92ade12c40c4"><pre>```language=bash
